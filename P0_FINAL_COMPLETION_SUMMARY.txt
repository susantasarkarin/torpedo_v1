## Critical Architectural Insight: CPX vs Cint

### The Core Difference

**CPX Entry Link Model** (Dynamic):
```
For each respondent:
  1. Fetch survey from API (cached)
  2. Append respondent parameters to URL
  3. Return dynamic URL
  
Example: 
  Base: https://cpx.com/survey?id=123
  Plus: &subid_1=respondent_X
  Result: https://cpx.com/survey?id=123&subid_1=respondent_X
```

**Cint Entry Link Model** (Static):
```
For each survey (once):
  1. Call Cint API to create entry link
  2. Store returned live_link in database
  3. live_link contains [%MID%] and [%REVENUE%] placeholders
  
For each respondent:
  1. Retrieve stored live_link from database
  2. Return AS-IS (do NOT modify)
  3. Cint replaces [%MID%] when respondent clicks
  
Example:
  Stored: https://cint.samplicio.us/entry?[%MID%]=...&[%REVENUE%]=...
  Returned: https://cint.samplicio.us/entry?[%MID%]=...&[%REVENUE%]=...
  (NO custom parameters appended)
```

### Why This Matters

The old code was treating Cint like CPX:
```python
# WRONG: Appending custom parameters
live_link = "https://cint.samplicio.us/entry?[%MID%]=..."
entry_url = live_link + "&rid=X&cc=Y"
# Result: https://cint.samplicio.us/entry?[%MID%]=...&rid=X&cc=Y
# Problem: Cint can't replace placeholders, custom params ignored
```

The new code respects Cint's architecture:
```python
# CORRECT: Use as-is
live_link = "https://cint.samplicio.us/entry?[%MID%]=..."
return live_link  # No modifications
# Result: https://cint.samplicio.us/entry?[%MID%]=...
# Success: Cint replaces [%MID%] when respondent clicks
```

## Security Features Implemented

1. **Webhook Signature Validation (HMAC-SHA256)**
   - Prevents URL spoofing
   - Authenticates Cint as sender
   - Fails on signature mismatch

2. **Idempotency**
   - Detects duplicate webhooks (within 5 second window)
   - Prevents duplicate credits
   - Logs all duplicates for audit

3. **Status Code Validation**
   - Only accepts known codes (10, 20, 30, 40, 50)
   - Rejects unknown codes immediately
   - Explicit error handling (no silent failures)

4. **HTTPS Enforcement**
   - Callback URL must use HTTPS in production
   - Prevents man-in-the-middle attacks

5. **Audit Trail**
   - All callbacks logged to outcomes collection
   - Tracks duplicates and errors
   - Enables compliance and debugging
