GMAIL ACCOUNT POOL MANAGEMENT
────────────────────────────────────────────────────────────────────────────

✓ Intelligent Account Rotation
  - 80% capacity threshold: 1600 sends/2000
  - Round-robin distribution within optimal threshold
  - Automatic fallback to least-used account if all heavily loaded
  - Prevents account suspension via rate balancing

✓ Account Selection Algorithm
  1. Get all active accounts with remaining capacity
  2. Sort by sends_today ASC (least used first)
  3. Filter for accounts < 1600 sends (80% threshold)
  4. Select first from filtered list (lowest usage)
  5. Fallback: Select least-used if all over threshold
  
  Example Flow:
  Accounts: [500, 1200, 1800 sends]
  Selected: Account with 500 (under 80% threshold, least used)

✓ Pool Statistics & Monitoring
  Returns:
  - total_capacity: Sum of all account limits (2000 each)
  - used: Total emails sent across all accounts today
  - available: Remaining capacity
  - percentage_used: Usage percentage
  - active_accounts: Count of active accounts
  - quota_exceeded: Count of rate-limited accounts
  - accounts: Per-account detailed statistics
  
  Use Case: Dashboard showing pool health in real-time

LINKEDIN AUTOMATION
───────────────────

# Single connection request
async with LinkedInAutomationService(db) as service:
    await service.initialize_session("email@example.com", headless=False)
    await service.login("email@example.com", "password", headless=False)
    
    result = await service.send_connection_request(
        profile_url="https://www.linkedin.com/in/john-doe/",
        note="Let's connect and discuss opportunities!",
        lead_id="lead_12345"
    )
    
    if result['success']:
        print(f"Connection sent to {result['profile_url']}")

# Batch send connections
results = await batch_send_connections(
    db,
    email="email@example.com",
    profiles=[
        {"profile_url": "https://...", "note": "Hi!", "lead_id": "lead_1"},
        {"profile_url": "https://...", "note": "Hi!", "lead_id": "lead_2"},
        {"profile_url": "https://...", "note": "Hi!", "lead_id": "lead_3"},
    ],
    delay_between=(45, 60)  # 45-60 seconds between requests
)

# Check daily activity
stats = await service.get_activity_stats()
print(f"Connections sent: {stats['connections_sent']}/100")
print(f"Messages sent: {stats['messages_sent']}/50")

KNOWN LIMITATIONS & WORKAROUNDS

LinkedIn:
1. 2FA Required First Login
   - Workaround: Use headless=False for first login
   - Sessions cached afterwards

2. No Direct API Access
   - Workaround: Playwright browser automation (current approach)
   - Slower but more reliable than API-based solutions

3. IP-based Rate Limiting
   - Workaround: Use VPN or residential proxies if sending at scale
   - LinkedIn may block repeated requests from same IP

4. Connection Note 150 Character Limit
   - Current: Truncates to 150 chars
   - Proper limit enforcement prevents error

5. Messaging Only to 1st Degree Connections
   - Design: Only connections can receive DMs
   - No pendingg connection requests

Gmail:
1. Account Suspension Risk
   - Mitigation: 80% threshold prevents rapid quota exhaustion
   - Monitor: Check pool_stats() regularly

2. IP Address Requirements
   - Workaround: Use residential IPs or Google-approved sources
   - LinkedIn: Same IP requirements as session auth
