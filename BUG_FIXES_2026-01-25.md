## Issue 1.2: Survey Allocation Not Working Properly

### Problem
After the button was clicked, the system was not properly allocating surveys from the "active" marked surveys in the survey pool. It was also not matching surveys by country code.

### Root Cause
The `/api/store` endpoint in `traffic.py` was:
1. Not filtering surveys by `is_active_in_pool=True`
2. Not matching surveys by country code
3. Only querying CPX surveys, not CINT surveys

### Solution
Completely rewrote the survey allocation logic to:
1. Query both CPX and CINT survey collections
2. Filter by `is_active_in_pool=True`
3. Match surveys by country code (for CPX)
4. Combine both pools and randomly select from active surveys
5. Generate proper entry links for both CPX and CINT surveys

### File Modified
- `backend/routers/traffic.py` (lines 640-752)

### Key Changes
```python
# Query for active CPX surveys matching country
cpx_query = {
    "is_active_in_pool": True,
    "country": cc_upper
}
cpx_surveys = list(cpx_collection.find(cpx_query).limit(50))

# Query for active CINT surveys
cint_query = {
    "is_active_in_pool": True
}
cint_surveys = list(cint_collection.find(cint_query).limit(50))

# Combine both pools and randomly select
all_surveys = cpx_surveys + cint_surveys
selected_survey = random.choice(all_surveys)
```

## Issue 2.2: CPX Entry Link Wrong

### Problem
The CPX entry link parameters were not fully compliant with the CPX API documentation.

### Root Cause
The `generate_entry_link` function in `cpx_service.py` was conditionally adding `username` and `email` parameters only if they were provided. According to the CPX API documentation, these parameters should always be included (even if empty).

### Solution
Updated the entry link generation to always include `username` and `email` parameters, even when they are empty strings.

### File Modified
- `backend/app/services/cpx_service.py` (lines 152-168)

### Code Change
```python
# Before (conditional)
if username:
    additional_params += f"&username={quote(username)}"
if email:
    additional_params += f"&email={quote(email)}"

# After (always included)
additional_params += f"&username={quote(username or '')}"
additional_params += f"&email={quote(email or '')}"
```

### CPX Entry Link Format (Per Documentation)
```
{live_link}&ext_user_id={unique_user_id}&app_id=10754&secure_hash={secure_hash}&username=&email=&subid_1=&subid_2=
```
