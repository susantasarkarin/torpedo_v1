## Critical Architectural Difference: CPX vs Cint

### Entry Link Generation (Why P0-2 Was Critical)

**CPX Pattern** (Dynamic):
```
1. Fetch surveys from API (cached)
2. For EACH respondent: append subid_1 to href
3. Result: href?subid_1=X  (respondent parameter)
```

**Cint Pattern** (Static):
```
1. For EACH survey: Call Cint API once
2. Store returned live_link in DB (has [%MID%] placeholder)
3. For EACH respondent: Use stored link AS-IS
4. Cint replaces [%MID%] when respondent clicks
```

**The Bug**: Previous code was using CPX pattern with Cint links
- `live_link` (from Cint) contains: `https://...?[%MID%]=...`
- `build_entry_link()` was appending: `&rid=X&cc=Y`
- Result: `https://...?[%MID%]=...&rid=X&cc=Y` ❌ WRONG
- Cint couldn't replace placeholders correctly ❌

**The Fix**: Use `live_link` directly without modification
- Just return: `https://...?[%MID%]=...` ✅ CORRECT
- Cint replaces `[%MID%]` when respondent clicks ✅
